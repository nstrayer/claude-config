# build-mcp-app reference

The rationale, the verified gotchas, and the variations. The scaffolded project
also carries the pattern-level decisions as ADRs (`docs/adr/`). This file is for
the agent doing the scaffolding.

## What the pattern is

An MCP server that runs as a single Cloudflare Worker and is consumable from the
Claude consumer app (web/desktop/iOS/Android) as a custom connector added by
URL. Pieces:

1. **`McpAgent` + `McpServer` over Streamable HTTP.** `src/index.ts` subclasses
   `McpAgent` (from `agents/mcp`), holds a `McpServer`, and registers tools in
   `init()`. `__CLASS_NAME__.serve("/mcp")` produces the fetch handler. The
   `McpAgent` is itself a Durable Object (required by `agents`), declared in
   `wrangler.jsonc` with a `new_sqlite_classes` migration.
2. **Secret-in-path auth.** The `fetch` wrapper accepts only
   `/<MCP_SECRET>/mcp`; everything else 404s. The consumer connector UI has no
   header field, so the URL itself is the credential. (ADR-0001.)
3. **Thin CRUD tools over storage.** One read + one write per store, plus
   delete. No coded analytics -- intelligence stays in Claude's reasoning over
   the data. Keeps tool-selection reliable.
4. **Optional MCP Apps widget.** An `open_view` dispatcher tool carries
   `_meta.ui.resourceUri`; a `ui://` resource serves bundled HTML as
   `text/html;profile=mcp-app`; a browser client (`client/widget.ts`) uses
   `@modelcontextprotocol/ext-apps` to seed from the tool result and write back
   via `callServerTool`. (ADR-0002.)
5. **Local verification scripts.** `verify-ui.mjs` (the `_meta.ui` + `ui://`
   wiring) and `smoke.mjs` (the CRUD tools) drive the server with the MCP SDK
   client over Streamable HTTP, so the protocol is proven before any phone test.

## Gotchas baked into the templates -- preserve them

- **Bundle the client, no CDN.** `build-ui.mjs` esbuilds `client/widget.ts` into
  an IIFE and inlines it into the served HTML string. Loading the ext-apps
  bridge from a CDN was flaky (`esm.sh ?bundle` failed; jsdelivr worked but is a
  runtime dependency + a CSP entry to avoid).
- **zod-locale alias is critical.** ext-apps pulls zod v4, which bundles ~40
  locale files (~190 KB). The `oneZodLocale` esbuild plugin aliases every
  non-`en` locale to `en`, roughly halving the bundle (~395 KB -> ~200 KB). If
  you change `build-ui.mjs`, keep this plugin and the
  `node_modules/zod/v4/locales/en.js` resolve path.
- **`_meta.ui` contract is exact.** The tool needs
  `_meta: { ui: { resourceUri, visibility: ["model","app"] } }`, and the
  registered resource's mimeType must be **exactly** `text/html;profile=mcp-app`.
  The host advertises the UI capability, not the server.
- **`updateModelContext` does not reach the model** on the consumer app (tested
  across model tiers). The store is the source of truth; the model only learns
  of widget writes by calling a tool. The widget re-reads (`list_items`) after a
  write; don't add a model-context push and assume the model sees it.
- **Auto-resize fires only after `app.connect()`.** Pre-connect, the inline card
  is clipped. Keep critical content visible early, connect fast, and keep a
  self-diagnosing status line for device debugging.
- **Seed via `ontoolresult` (and `ontoolinput`), with a `callServerTool`
  fallback.** The host delivers the initiating tool's `CallToolResult` to the
  widget; if it never arrives, fetch the data yourself after a short delay.
- **tsconfig `include: ["src/**/*.ts"]`** deliberately excludes `client/`, so
  the browser widget (typed for the DOM, not Workers) does not break the Worker
  typecheck. esbuild handles the client.
- **The generated `src/ui/widget-html.ts` is gitignored** and regenerated by
  `build:ui`, which is wired into `dev`/`deploy`/`typecheck`.

## Bundle size: a known upstream issue, not a misconfiguration

The widget bundle looks alarming but mostly isn't. Measured composition of the
example widget:

```
197 KB minified  ->  ~53 KB gzip  ->  ~45 KB brotli (what Cloudflare serves)
  zod                       ~69%   (the protocol validator)
  @modelcontextprotocol/*   ~29%   (ext-apps App + SDK Protocol)
  your widget code           ~2%
```

So the over-the-wire cost is ~45 KB, loaded once for an inline card -- fine. The
197 KB is uncompressed and ~98% the MCP Apps client SDK, not your code. zod is
**load-bearing**: ext-apps' `PostMessageTransport` `safeParse`s every inbound
message and the SDK `Protocol` `.parse()`s every response against a zod schema.
It is not removable downstream.

This is a tracked upstream problem, and the locale fix we ship is the accepted
workaround for one half of it:

- **ext-apps #665** -- `import * as z from "zod/v4"` re-exports `* as locales`,
  defeating tree-shaking, so ~40 locale files (~190 KB) bundle. Our
  `oneZodLocale` esbuild alias is the same fix the issue reporter used (theirs is
  a Vite plugin). This is what takes the bundle from ~386 KB to ~197 KB.
- **ext-apps #649** -- the bridge pulls in nearly all of zod (~84% of the bundle
  before the locale fix), un-tree-shakeable because of how the SDK imports it.
  This is the remaining ~137 KB. Open, unfixed.
- **typescript-sdk #809 (SDK v2)** -- maintainers plan to decouple zod (bring
  your own validator) and split `-client`/`-server`. When that lands, the bundle
  shrinks for free, no fork.

Levers that do NOT work downstream: you cannot substitute `zod/mini` (the SDK
imports full `zod/v4`; adopting mini is an upstream ask in #649), and you cannot
`external`-ize zod (the schemas are constructed and `.parse()`d at runtime).

**Escape hatch (only for a hard size budget):** stop using ext-apps + the SDK and
hand-roll a minimal postMessage JSON-RPC bridge -- the `ui/initialize` handshake
(`protocolVersion: "2026-01-26"`), request/response correlation, one `tools/call`
request, the `ui/notifications/tool-result` + `tool-input` notifications, and a
`ResizeObserver` -> `ui/notifications/size-changed`. ~100-150 lines, zero deps,
~197 KB -> ~5-7 KB. The cost is owning protocol-drift and correctness against an
evolving spec, which is exactly what using ext-apps buys you. Track #649/#809
instead unless the budget is truly hard.

## Intake variations

### Storage: KV (default) vs Durable Object SQL

The template uses Workers KV (binding `STORE`) for app data -- simple, global,
fine for a personal tool. The `McpAgent` is always a Durable Object regardless.
If the user wants stronger consistency, per-entity rows, or transactional
updates, switch the app data to the Durable Object's own SQLite storage
(`this.sql` / `this.storage` on the agent) instead of KV: drop the
`kv_namespaces` block and the `STORE` binding, and read/write through the DO.
Keep everything else (auth, tools, widget) identical.

### Strip the UI (if the user does NOT want the MCP Apps widget)

After scaffolding, remove the widget pieces:

1. Delete `client/`, `scripts/build-ui.mjs`, and `scripts/verify-ui.mjs`.
2. In `src/index.ts`: remove the `import { WIDGET_HTML }` line, the
   `registerResource("views", ...)` block, and the `open_view` tool.
3. In `package.json`: remove `@modelcontextprotocol/ext-apps` and `esbuild` from
   devDependencies, the `build:ui` script, and the `npm run build:ui &&` prefix
   from `dev`/`deploy`/`typecheck`.
4. In `.gitignore`: remove the `src/ui/widget-html.ts` line.
5. Delete `docs/adr/0002-mcp-apps-widgets.md`.

### Auth

Default is secret-in-path (ADR-0001) because it is the only thing the consumer
connector UI supports. For a local-only or non-connector server you can drop the
`fetch` wrapper and serve `/mcp` directly. For production / multi-user, replace
it with OAuth 2.1 via Cloudflare `workers-oauth-provider`.

## Dependencies (pinned to the proven set)

Runtime: `agents`, `@modelcontextprotocol/sdk`, `zod`. Dev: `esbuild`,
`@modelcontextprotocol/ext-apps`, `wrangler`, `@cloudflare/workers-types`,
`typescript`. Versions in `templates/package.json` match a working build; bump
deliberately, and re-run the local verify after any bump.

## Deploy + connector setup

In the generated README.md. Summary: `wrangler kv namespace create STORE` ->
paste the id into `wrangler.jsonc` -> `npm run deploy` -> set `MCP_SECRET` with
`wrangler secret put` -> smoke-test the prod URL -> add the full
`https://.../<MCP_SECRET>/mcp` URL as a custom connector on claude.ai (leave
OAuth fields blank). Needs Claude Pro/Max; it syncs to mobile automatically.
