# build-mcp-app reference

The rationale, the verified gotchas, and the variations. The scaffolded project
also carries the pattern-level decisions as ADRs (`docs/adr/`). This file is for
the agent doing the scaffolding.

## What the pattern is

An MCP server that runs as a single Cloudflare Worker and is consumable from the
Claude consumer app (web/desktop/iOS/Android) as a custom connector added by
URL. Pieces:

1. **`McpAgent` + `McpServer` over Streamable HTTP.** `src/index.ts` subclasses
   `McpAgent` (from `agents/mcp`), holds a `McpServer`, and registers tools in
   `init()`. `__CLASS_NAME__.serve("/mcp")` produces the fetch handler. The
   `McpAgent` is itself a Durable Object (required by `agents`), declared in
   `wrangler.jsonc` with a `new_sqlite_classes` migration.
2. **Secret-in-path auth.** The `fetch` wrapper accepts only
   `/<MCP_SECRET>/mcp`; everything else 404s. The consumer connector UI has no
   header field, so the URL itself is the credential. (ADR-0001.)
3. **Thin CRUD tools over storage.** One read + one write per store, plus
   delete. No coded analytics -- intelligence stays in Claude's reasoning over
   the data. Keeps tool-selection reliable.
4. **MCP Apps widget (React + Tailwind).** An `open_view` dispatcher tool carries
   `_meta.ui.resourceUri`; a `ui://` resource serves bundled HTML as
   `text/html;profile=mcp-app`. The client (`client/widget.tsx`) is a React
   component using `@modelcontextprotocol/ext-apps/react` (`useApp`,
   `useHostStyleVariables`) to seed from the tool result and write back via
   `callServerTool`, styled with Tailwind (`client/app.css`). `build-ui.mjs`
   bundles the React app (esbuild) and generates the Tailwind CSS (PostCSS) and
   inlines both into one HTML string. (ADR-0002.)
5. **Local verification scripts.** `verify-ui.mjs` (the `_meta.ui` + `ui://`
   wiring) and `smoke.mjs` (the CRUD tools) drive the server with the MCP SDK
   client over Streamable HTTP, so the protocol is proven before any phone test.

## Gotchas baked into the templates -- preserve them

- **Bundle everything, no CDN.** `build-ui.mjs` esbuilds `client/widget.tsx`
  (React, production, `jsx: "automatic"`, `NODE_ENV=production`) into an IIFE and
  inlines it plus the build-time Tailwind CSS into one served HTML string. Never
  load React, the ext-apps bridge, or the Tailwind Play CDN at runtime: a CDN dep
  is a load-time failure point and a CSP entry to avoid, and the Tailwind Play CDN
  additionally does in-browser JIT (eval) that violates CSP. Tailwind must run at
  build time.
- **Theming uses host CSS variables.** The widget calls `useHostStyleVariables`,
  and `client/app.css` maps a few Tailwind theme tokens (`--color-fg`,
  `--color-accent`, ...) to the host's variables with light fallbacks, so it
  matches the host's palette + light/dark with no class toggling.
- **zod-locale alias is critical.** ext-apps pulls zod v4, which bundles ~40
  locale files (~190 KB). The `oneZodLocale` esbuild plugin aliases every
  non-`en` locale to `en`, roughly halving the bundle (~395 KB -> ~200 KB). If
  you change `build-ui.mjs`, keep this plugin and the
  `node_modules/zod/v4/locales/en.js` resolve path.
- **`_meta.ui` contract is exact.** The tool needs
  `_meta: { ui: { resourceUri, visibility: ["model","app"] } }`, and the
  registered resource's mimeType must be **exactly** `text/html;profile=mcp-app`.
  The host advertises the UI capability, not the server.
- **`updateModelContext` does not reach the model** on the consumer app (tested
  across model tiers). The store is the source of truth; the model only learns
  of widget writes by calling a tool. The widget re-reads (`list_items`) after a
  write; don't add a model-context push and assume the model sees it.
- **Auto-resize fires only after `app.connect()`.** Pre-connect, the inline card
  is clipped. Keep critical content visible early, connect fast, and keep a
  self-diagnosing status line for device debugging.
- **Seed via `ontoolresult` (and `ontoolinput`), with a `callServerTool`
  fallback.** The host delivers the initiating tool's `CallToolResult` to the
  widget; if it never arrives, fetch the data yourself after a short delay.
- **tsconfig `include: ["src/**/*.ts"]`** deliberately excludes `client/`, so the
  React widget (typed for the DOM, not Workers) does not break the Worker
  typecheck. esbuild builds the `.tsx` -- which means the widget itself is not
  type-checked by `tsc`; run your editor or a separate `tsc` over `client/` if
  you want that.
- **The generated `src/ui/widget-html.ts` is gitignored** and regenerated by
  `build:ui`, which is wired into `dev`/`deploy`/`typecheck`.

## Bundle size: mostly fixed library cost (+ a known upstream zod issue)

The bundle looks big but is dominated by libraries, not your code. Measured for
this template (React + Tailwind, validated):

```
~396 KB min  ->  ~114 KB gzip  ->  ~98 KB brotli (what Cloudflare serves)
  react-dom                 ~50%
  zod (protocol validator)  ~35%
  ext-apps App + SDK        ~13%
  Tailwind CSS (~9.6 KB)     ~2%
  your widget code           <1%
```

~98 KB brotli, loaded once for an inline card, is acceptable -- but ~2x the
no-React baseline (~45 KB brotli). Two independent things drive it:

**1. React.** react-dom is ~half the bundle. For a hard budget, alias to Preact:
in `build-ui.mjs` add
`alias: { react: "preact/compat", "react-dom": "preact/compat", "react-dom/client": "preact/compat", "react/jsx-runtime": "preact/jsx-runtime" }`
and add `preact` as a dep. **Caveat:** `preact/compat` does not export
`createRoot`, so change the mount in `widget.tsx` to
`import { render } from "preact/compat"; render(<Widget />, document.getElementById("root")!)`.
That drops React's share to a few KB (roughly back toward the ~50 KB-brotli
range). Verified that the plain `react`/`react-dom` -> `preact/compat` alias fails
the build on `createRoot` until you make that change.

**2. zod (load-bearing, a tracked upstream issue).** zod is ~35% even after our
locale fix, and is not removable downstream: ext-apps' `PostMessageTransport`
`safeParse`s every inbound message and the SDK `Protocol` `.parse()`s every
response against a zod schema. The locale fix we ship is the accepted workaround
for one half of the bloat:

- **ext-apps #665** -- `import * as z from "zod/v4"` re-exports `* as locales`,
  defeating tree-shaking, so ~40 locale files (~190 KB) bundle. Our `oneZodLocale`
  esbuild alias is the same fix the reporter used (theirs is a Vite plugin).
- **ext-apps #649** -- the bridge pulls in nearly all of zod, un-tree-shakeable
  because of how the SDK imports it. The residual zod weight. Open, unfixed.
- **typescript-sdk #809 (SDK v2)** -- maintainers plan to decouple zod (bring
  your own validator) + split `-client`/`-server`. When it lands, this shrinks
  for free, no fork.

You cannot substitute `zod/mini` (the SDK imports full `zod/v4`; that is an
upstream ask in #649) or `external`-ize zod (schemas are `.parse()`d at runtime).

**Nuclear option (hard budget only):** drop ext-apps + the SDK and hand-roll a
postMessage JSON-RPC bridge -- the `ui/initialize` handshake
(`protocolVersion: "2026-01-26"`), request/response correlation, one `tools/call`,
the `tool-result`/`tool-input` notifications, and a `ResizeObserver` ->
`size-changed`. Sheds zod entirely, but you own protocol-drift against an evolving
spec -- which is exactly what using ext-apps buys you. Track #649/#809 instead
unless the budget is truly hard.

## Intake variations

### Storage: KV (default) vs Durable Object SQL

The template uses Workers KV (binding `STORE`) for app data -- simple, global,
fine for a personal tool. The `McpAgent` is always a Durable Object regardless.
If the user wants stronger consistency, per-entity rows, or transactional
updates, switch the app data to the Durable Object's own SQLite storage
(`this.sql` / `this.storage` on the agent) instead of KV: drop the
`kv_namespaces` block and the `STORE` binding, and read/write through the DO.
Keep everything else (auth, tools, widget) identical.

### Strip the UI (if the user does NOT want the MCP Apps widget)

After scaffolding, remove the widget pieces:

1. Delete `client/`, `scripts/build-ui.mjs`, and `scripts/verify-ui.mjs`.
2. In `src/index.ts`: remove the `import { WIDGET_HTML }` line, the
   `registerResource("views", ...)` block, and the `open_view` tool.
3. In `package.json`: remove the widget deps (`react`, `react-dom`,
   `@modelcontextprotocol/ext-apps`, `@types/react`, `@types/react-dom`,
   `tailwindcss`, `@tailwindcss/postcss`, `postcss`, `esbuild`), the `build:ui`
   script, and the `npm run build:ui &&` prefix from `dev`/`deploy`/`typecheck`.
4. In `.gitignore`: remove the `src/ui/widget-html.ts` line.
5. In `tsconfig.json`: remove the `"jsx"` line. Delete
   `docs/adr/0002-mcp-apps-widgets.md`.

### Auth

Default is secret-in-path (ADR-0001) because it is the only thing the consumer
connector UI supports. For a local-only or non-connector server you can drop the
`fetch` wrapper and serve `/mcp` directly. For production / multi-user, replace
it with OAuth 2.1 via Cloudflare `workers-oauth-provider`.

## Dependencies (pinned to the proven set)

Runtime: `agents`, `@modelcontextprotocol/sdk`, `zod`, `react`, `react-dom`. Dev:
`esbuild`, `@modelcontextprotocol/ext-apps`, `tailwindcss`, `@tailwindcss/postcss`,
`postcss`, `@types/react`, `@types/react-dom`, `wrangler`,
`@cloudflare/workers-types`, `typescript`. Versions in `templates/package.json`
match a working build; bump deliberately, and re-run the local verify after any
bump.

## Deploy + connector setup

In the generated README.md. Summary: `wrangler kv namespace create STORE` ->
paste the id into `wrangler.jsonc` -> `npm run deploy` -> set `MCP_SECRET` with
`wrangler secret put` -> smoke-test the prod URL -> add the full
`https://.../<MCP_SECRET>/mcp` URL as a custom connector on claude.ai (leave
OAuth fields blank). Needs Claude Pro/Max; it syncs to mobile automatically.
